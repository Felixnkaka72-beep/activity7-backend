# Campus Maintenance Requests API

Independent Node.js + Express backend for the Campus Maintenance Requests system (ICT251 Activity 7). Records are stored in a PostgreSQL database and every route returns JSON. It does not need a browser or the Activity 6 frontend.

## Routes
| Method | Route | Purpose | Success |
|---|---|---|---|
| GET | / | API guide and in-browser tester (HTML) | 200 |
| GET | /health | Server and database check | 200 (503 if database fails) |
| GET | /api/records | Read all records | 200 |
| GET | /api/records/:id | Read one record | 200 |
| POST | /api/records | Create a record | 201 |
| PUT | /api/records/:id | Update a record | 200 |
| DELETE | /api/records/:id | Delete a record | 200 `{"message":"Record deleted."}` |

Errors return `{"message": "..."}` with 400 (invalid input, invalid id, malformed JSON), 404 (record or route not found), 413 (body too large), 500 (unexpected failure).

Fields (same names as Activity 6): `id` (generated by the database, never sent by the client), `title` 3-80, `category` 2-40, `description` 5-300, `status` = `Pending`, `In progress` or `Completed`. Text is checked to be a string, then trimmed, then length-checked.

## Files
| File | Purpose |
|---|---|
| `server.js` | Express app, middleware, guide page, health route, 404 and error handlers |
| `routes/records.js` | The five record routes and validation |

| `setup.js` | Runs both SQL files; the server calls it at start-up, or run `npm run setup` |
| `test-api.js` | Automatic check of every assignment test (`npm run test:api`) |
| `.env.example` | Copy to `.env`; never upload `.env` |

## Run locally
1. Install Node.js LTS. Open a terminal in this folder (PowerShell: use `npm.cmd` if `npm` is blocked).
2. `npm install express cors dotenv pg`
3. Create a PostgreSQL database (see Host on Render) and copy its connection URL.
4. Copy `.env.example` to `.env` and set `DATABASE_URL`.
5. `npm start`, then open http://localhost:3000 (the tables and 8 records are created automatically).

## Test
- Automatic: with the server running, `node test-api.js` (local) or `node test-api.js https://your-backend.onrender.com` (hosted). It checks every row of the assignment test table.
- Manual: use Postman, or the "Try the API here" panel on the guide page. POST/PUT body:
```json
{ "title": "Broken classroom light", "category": "Electrical",
  "description": "The light in Room B12 does not switch on.", "status": "Pending" }
```
- Persistence (by hand): create a record, stop and restart the server, GET it again.

## Requirements checklist
| Requirement | Where |
|---|---|
| Express API with GET, POST, PUT, DELETE | `routes/records.js` |
| `/` guide with name, student number, URL, links, routes, fields, body, status codes, idle note | `server.js` |
| `/health` checks the database (200 / 503) | `server.js` |
| Validation: string check, trim, lengths, exact status, id check, client id ignored | `routes/records.js` |
| 400 / 404 / 500 JSON errors, unknown-route handler, 4-parameter error middleware | `server.js` |
| Placeholders (`$1`) in every query | `routes/records.js` |
| Ids generated by the database | `schema.sql` |
| 8+ made-up records inserted once | `seed.sql` |
| Persistent hosted database | PostgreSQL |
| `.gitignore` excludes `.env` and `node_modules`; CommonJS; `npm start` | project root |

## Host on Render
1. Push this folder to GitHub (include `package.json` and `package-lock.json`; exclude `.env` and `node_modules`).
2. Render: New > Postgres (Free). Copy the Internal Database URL (for the web service) and the External Database URL (for running locally).
3. Render: New > Web Service > connect the repository. Build `npm install`, start `npm start`, Free instance.
4. Environment variables: `DATABASE_URL` (Internal URL) and `CLIENT_ORIGINS` (your frontend address, no trailing slash).
5. Deploy, read the logs, open the HTTPS URL, check `/health`, then run `node test-api.js <your URL>`.

Free web services sleep when idle, so the first request can take about a minute. Free Render Postgres databases expire 30 days after creation.
